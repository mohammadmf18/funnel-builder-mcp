# Funnel Builder — بناء فنلات عربية عبر MCP وREST

أدوات لإنشاء صفحات فنل عربية، ربطها حسب ترتيب الإضافة، ونشرها محليًا عبر FastAPI مع حفظ المشتركين في SQLite وتتبع الزيارات والتسجيلات.

**المتاح فعليًا:** صفحة هبوط ← نموذج تسجيل يحفظ الإيميل ← صفحة شكر، وأدوات لإدارة المحتوى والمشتركين والتحليلات. يمكن إضافة صفحات بيع وروابط دفع خارجية.

**حدود النسخة:** ليست خدمة استضافة سحابية. الدفع يتطلب رابط HTTPS من مزود دفع، ولا يتم تأكيد المشتريات تلقائيًا أو منح وصول مدفوع. تسلسلات الإيميلات مسودات محفوظة فقط؛ لا يوجد إرسال أو جدولة أو تسليم تلقائي للهدايا. يلزم تكامل مع مزود إرسال وwebhooks موثوقة للدفع لهذه الوظائف.

## المتطلبات والتثبيت

Python 3.10 أو أحدث:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

على Windows: استخدم `.venv\Scripts\activate`.

## التشغيل

أنشئ مفتاحًا عشوائيًا لإدارة الأدوات، ثم شغّل الخادم:

```bash
export FUNNEL_API_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
uvicorn api_server:app --host 127.0.0.1 --port 8000
```

احتفظ بالمفتاح لاستدعاءاتك الإدارية، ولا تضعه في صفحات الزوار. عند غياب المفتاح ترفض `/tools` و`/tools/call` الطلبات برمز 503. المفتاح الخاطئ أو المفقود يرجع 401. الصفحات ونموذج الاشتراك عامة، وMCP المحلي يعتمد على صلاحية الوصول إلى عملية stdio.

```bash
curl http://127.0.0.1:8000/tools \
  -H "Authorization: Bearer $FUNNEL_API_KEY"

curl http://127.0.0.1:8000/tools/call \
  -H "Authorization: Bearer $FUNNEL_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"name":"create_funnel","arguments":{"name":"نشرة التسويق","goal":"جمع الاشتراكات"}}'
```

واجهة الإدارة مناسبة لمشغّل واحد موثوق؛ لا يوجد فصل حسابات أو صلاحيات بين مستخدمين مختلفين.

## تجربة كاملة بدون نموذج ذكاء اصطناعي

من مجلد المشروع، في نافذة طرفية ثانية وبنفس إعدادات قاعدة البيانات:

```bash
python - <<'PY'
import core
funnel_id = core.create_funnel('نشرة التسويق', 'جمع الاشتراكات')['funnel_id']
core.add_landing_page(funnel_id, 'أفكار تسويقية تصلك مباشرة', 'سجّل بريدك لتبقى على اطلاع', 'سجّل الآن')
core.add_optin_page(funnel_id, 'انضم للقائمة', 'أدخل بريدك الإلكتروني')
core.add_thankyou_page(funnel_id, message='تم حفظ اشتراكك بنجاح.')
result = core.publish_funnel(funnel_id)
print('http://127.0.0.1:8000' + result['site_path'])
PY
```

افتح الرابط، اضغط الزر، وأرسل بريدًا صالحًا. يتم حفظ المشترك ثم الانتقال إلى صفحة الشكر. `list_leads` يعرض المشتركين؛ `get_funnel_analytics` يعرض النتائج. إعادة إرسال البريد نفسه في الفنل لا تنشئ مشتركًا أو حدث تسجيل إضافيًا. تتم مقارنة عناوين البريد دون حساسية لحالة الأحرف.

## أدوات الذكاء الاصطناعي

التعريفات في `schemas.py` هي المصدر نفسه لـMCP وOpenAI، ويتم التحقق منها قبل التنفيذ، بما يشمل رفض الحقول غير المعروفة والأسعار السالبة. تعديلات محتوى الصفحات تخضع للتحقق حسب نوع الصفحة.

| الأداة | الوظيفة |
|---|---|
| `create_funnel`, `list_funnels`, `get_funnel`, `delete_funnel` | إدارة الفنلات؛ الحذف يزيل بياناتها وملفاتها المحلية |
| `add_landing_page`, `add_optin_page`, `add_sales_page` | إضافة صفحات هبوط وتسجيل وبيع |
| `add_checkout_page`, `add_upsell_page` | صفحات تربط إلى مزود دفع خارجي عبر `checkout_url`؛ دون الرابط لا يظهر زر دفع فعّال |
| `add_thankyou_page`, `update_page` | إضافة صفحة شكر وتعديل المحتوى |
| `publish_funnel` | توليد HTML وJavaScript وإرجاع مسار الصفحة المحلية |
| `list_leads` | عرض المشتركين، مع `limit` و`offset` |
| `connect_email_sequence` | حفظ مسودة رسائل، مع `sending_enabled: false` |
| `record_event`, `get_funnel_analytics` | أحداث موثوقة من الإدارة وتقارير الفنل |

`add_sales_page` يتطلب `benefits` كقائمة نصوص. `checkout_url` اختياري ويجب أن يكون HTTPS بدون بيانات اعتماد. إضافة رابط دفع لا تعني أن المدفوعات مؤكدة أو متتبعة تلقائيًا؛ اضبط العودة للصفحة المناسبة في مزود الدفع وأضف webhook للتحقق قبل تسليم أي منتج مدفوع. زيارة صفحة الشكر لا تثبت حصول دفع.

### MCP عبر stdio

أضف إعدادًا في عميل MCP الذي تستخدمه، مع استبدال المسارات بمسارات مطلقة فعلية:

```json
{
  "mcpServers": {
    "funnel-builder": {
      "command": "/absolute/path/funnel-builder-mcp/.venv/bin/python",
      "args": ["/absolute/path/funnel-builder-mcp/mcp_server.py"]
    }
  }
}
```

الخادم يستهدف MCP Python SDK v1، ويستخدم التعريفات والتحقق نفسيهما اللذين يستخدمهما REST. اطلب: «أنشئ فنلًا لجمع المشتركين، بصفحة هبوط وتسجيل وشكر، ثم انشره». تشغيل خادم HTTP مطلوب لفتح الصفحات وحفظ التسجيلات حتى لو أُنشئ الفنل عبر MCP.

### مثال OpenAI

```bash
export OPENAI_API_KEY="your-key"
# اختياري: OPENAI_MODEL لتغيير النموذج المستخدم في المثال
python example_openai_client.py
```

المثال ينفذ الأدوات محليًا، ويحد المحادثة باثنتي عشرة جولة. تشغيله يستدعي خدمة OpenAI ويتطلب مفتاحًا ورصيدًا؛ لا تحتاجه لتجربة المشروع الأساسية.

## البيانات والنشر والتحليلات

- `FUNNEL_DB_PATH`: مسار قاعدة البيانات، افتراضيًا `funnels.db` بجانب الكود. الترقية تضيف جدول المشتركين وحقل الزائر تلقائيًا مع حفظ البيانات السابقة.
- `FUNNEL_OUTPUT_DIR`: مجلد ملفات المواقع، افتراضيًا `generated_sites` بجانب الكود. لا يقبل استدعاء أداة النشر مسارًا من العميل.
- الصفحات تتصل حسب ترتيب إضافتها. أعد `publish_funnel` بعد تعديل الصفحات أو إضافتها؛ أعد نشر الفنلات القديمة للحصول على نموذج التسجيل والملف البرمجي الجديد.
- رفع HTML وحده إلى استضافة ثابتة يعرض التصميم والتنقل، لكنه لا يحفظ الاشتراكات. الوظائف الكاملة تتطلب هذا الخادم ومسارات `/sites/` على الأصل نفسه. النشر العام يحتاج استضافة Python وHTTPS؛ لا ينفّذ المشروع نشرًا سحابيًا تلقائيًا.
- زيارات الصفحات عبر الخادم تسجّل تلقائيًا. `visits` يعدّ الزائر مرة واحدة لكل فنل حسب ملف تعريف ارتباط مدته 30 يومًا، بينما الأحداث اليدوية القديمة بدون معرف زائر تُعد منفردة. تغيير المتصفح أو حذف الكوكي يغيّر العدّ؛ ليست هذه قياسات هوية مؤكدة.
- `optins` يعدّ الاشتراكات الجديدة. أحداث الشراء والإيراد تأتي من استدعاءات `record_event` الإدارية، وليس من زر الدفع أو فتح صفحة الشكر. استخدم عملة واحدة لكل فنل لأن التقرير يجمع القيم دون تحويل العملات.
- قبل توسيع الاستخدام العام، أضف حماية من إساءة إرسال النماذج بحسب استضافتك، وتحقق بريدًا مزدوجًا إذا احتجت إثبات ملكية البريد. احرص على النسخ الاحتياطي لقاعدة البيانات؛ النموذج لا يتحقق من ملكية عنوان البريد.

## الاختبارات

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

الاختبارات تستخدم قواعد بيانات ومواقع مؤقتة، وتغطي رحلة التسجيل، التكرار، المصادقة، المدخلات، تهريب HTML، ملكية الأحداث، ترقية قاعدة البيانات، الحذف، واتصال MCP فعليًا عبر stdio. GitHub Actions يشغلها على Python 3.10 و3.12 و3.13.

## هيكل المشروع

- `core.py`, `db.py`: منطق الفنلات والتخزين.
- `schemas.py`, `validation.py`: تعريف الأدوات والتحقق.
- `mcp_server.py`, `api_server.py`: MCP وHTTP.
- `templates.py`, `funnel.js`: الصفحات ونموذج التسجيل.

## ربط MCP بالنسخة المستضافة

يمكن تشغيل MCP المحلي كوصلة إلى الخدمة السحابية بدل قاعدة SQLite المحلية. أنشئ ملف JSON خاصًا خارج المستودع بصلاحية `600`:

```json
{"url":"https://your-host.example","api_key":"your-management-key"}
```

اضبط `FUNNEL_CONNECTION_FILE` في إعدادات خادم MCP إلى المسار المطلق لهذا الملف. في هذا الوضع تُقرأ تعريفات الأدوات من الخادم المستضاف وتُنفّذ جميع العمليات عليه، بما فيها `list_leads` و`publish_funnel`. لا يحدث انتقال تلقائي إلى قاعدة محلية عند تعذر الاتصال، لتجنب تشتت البيانات. يُعاد عنوان عام من أداة النشر السحابية.

لا ترفع ملف الاتصال أو المفتاح إلى Git. بعد تعديل إعدادات MCP، افتح محادثة جديدة أو أعد تحميل العميل ليقرأها. البروتوكول البعيد المطلوب هو واجهة `/tools` و`/tools/call`؛ هذا الملف لا يغيّر إعدادات خدمة OpenAI ولا يحتاج مفتاح OpenAI إضافيًا.
